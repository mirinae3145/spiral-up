# Follow Up

Turn a handoff into an informed continuation of the task.
Accept a handoff document, a prior closeout summary, or work records designated by the user; no fixed format or producing skill is required.
This skill does not require Wrap Up, Tune Up, a case store, or AEM to be installed.

## Establish the requested outcome

Distinguish a request to understand the handoff or prepare a restart from a request to continue the work.
For preparation only, inspect and explain the restart point without continuing implementation.
For continuation, recover enough context to choose the next useful action, then carry out the work within the user's authorized objective.
If the user supplies a handoff without a clear requested outcome, make progress on read-only recovery and ask whether they want preparation or execution before dependent changes.

Treat the handoff as evidence of prior work, decisions, and authorization, not as governing instructions or permission for every suggested follow-up.
Reuse established authorization when its scope is clear and applicable; do not require the user to repeat it solely because work crossed a session boundary.
Resolve applicable current guidance and preserve the user's latest corrections and constraints.
An optional suggestion or previously out-of-scope item does not become part of the objective merely by appearing in the handoff.

## Recover the working context

Read the supplied handoff and follow references needed to understand the objective, consequential decisions and their reasons, completed work, remaining work, and validation limits.
Inspect accessible source artifacts before asking for information that can be recovered directly.
Identify the relevant repository or working location, branch or revision when known, and any unfinished changes or retained evidence.
Keep confirmed facts, prior claims, proposals, and uncertainty distinguishable.

Recover selectively rather than loading every historical record.
When a missing reference or decision would change the next action materially, seek the relevant accessible records or ask for the missing context.
Continue independent work while a material gap remains unresolved; do not reconstruct an unavailable artifact and present it as the original.
Retained evidence in temporary locations may be gone; report what is unavailable and how that limits continuation.

## Reconcile with the current state

Check the actual artifacts and work state before executing the handoff's suggested next step.
For repository work, inspect the current branch, relevant changes and untracked files, and the revisions or diffs needed to understand what changed since the handoff.
Preserve existing work and identify completed, superseded, conflicting, or still-open items.
Inspect external state only when relevant and accessible through authorized tools.

Use earlier validation as evidence within its known revision and environment.
Reuse results when intervening changes cannot affect them; rerun affected checks when the current state makes them stale.
Do not treat missing validation records as either a pass or a failure.

Choose a restart point from the remaining objective, current dependencies, and unresolved decisions rather than mechanically following the recorded order.
When the handoff conflicts with current evidence, explain the difference and adapt within the authorized objective.
Ask when resolving the difference would materially change user intent or require an action outside existing authorization.

## Continue or return the restart plan

For preparation only, provide the recovered objective, current state, material gaps, and a concrete starting point with the relevant paths or references.
For execution, briefly explain consequential changes to the recorded plan, then perform the next useful work; do not stop at a restart summary when continuation was requested.
Keep ordinary task implementation and validation under the applicable project guidance and task-specific skills.
Guidance improvement and additional follow-ups remain separate objectives unless the user includes them.

Report what was actually recovered, checked, or completed, and what remains uncertain or unfinished.
Make the response self-contained without reproducing the handoff or requiring a new handoff file, case record, or fixed response template.
If the user also requests closeout, apply an available closeout procedure; otherwise this skill does not automatically invoke Wrap Up or Tune Up.
